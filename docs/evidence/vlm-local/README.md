# 로컬 소형 VLM(SmolVLM-500M-Instruct, CPU) 실행 기록

환경: 4 vCPU, transformers 5.22, torch 2.15(CPU), 네트워크 허용 후 가중치 다운로드(≈1 GB, 40초).

| 시도 | 프롬프트 | 입력 | 지연 | 결과 |
|---|---|---|---|---|
| 1 | 한국어 시스템 프롬프트 + JSON 스키마 전문, 3프레임(768px, 이미지 분할 기본) | 입력 토큰 ≈ 7천 이상 | **>9분**(10분 타임아웃) | 측정 불가 — 분할된 이미지 토큰이 너무 많음 |
| 1' | 같은 프롬프트, 이미지 분할 끔·512px·2프레임 | 1,168 토큰 | 25초 | JSON-LD 형태의 무관한 텍스트(`@context`…) — 스키마 미준수 |
| 2 | 영어 압축 프롬프트 + 같은 장면의 예시 JSON | ≈1.2천 | ≈25초 | 예시 문장을 거의 그대로 복제, `activity` 누락 |
| 3 | 다른 장면(하역장) 예시 + 복제 검출 | ≈1.2천 | ≈25초 | `reasons`를 객체 배열로 출력(스키마 위반), 예시 문구 일부 복제 |

결론: 500M급 모델은 CPU에서 지연은 감당되지만 **구조화 출력·장면 기술 모두 신뢰할 수 없어** CV+VLM 비교에 쓰지 않았습니다(수치로 보고하지 않음). 워커의 스키마 검증·예시 복제 검출이 이런 출력을 `invalid`로 분류합니다. 더 큰 모델(SmolVLM-2.2B)은 별도 기록, API 모델(Claude)은 사용자 승인 후 GitHub Actions에서 실행했습니다(`docs/eval/vlm-findings.md`).
