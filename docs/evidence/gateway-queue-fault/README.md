# 게이트웨이 디스크 큐: 쓰기가 실패한 뒤 받은 사건이 사라지는 결함

게이트웨이의 디스크 큐(`gateway/internal/queue`)를 다시 구현하기 전에, 원래 코드에서 결함을 재현한 기록입니다(2026-11-24, 커밋 `eab3df6`).

## 결함

- 큐는 레코드를 파일 끝에 이어 붙입니다. 재시작하면 파일을 처음부터 읽다가 믿을 수 없는 레코드를 만나면 거기서 멈추고 그 뒤를 잘라 냅니다.
- 디스크가 가득 차면 쓰기가 레코드 중간에서 멈출 수 있습니다. 원래 코드는 이때 오류를 돌려주지만, 파일에 남은 반쪽 레코드는 그대로 둡니다.
- 디스크에 자리가 다시 생기면 다음 사건은 그 반쪽 레코드 뒤에 정상으로 기록되고, 분석기는 `accepted=true`를 받습니다.
- 재시작하면 복구가 반쪽 레코드에서 멈춥니다. 그 뒤에 받은 사건은 전부 잘려 나갑니다. "받았다고 답한 사건은 서버가 확인할 때까지 남는다"는 약속이 깨집니다.

## 재현

원래 코드는 파일을 `os.OpenFile`로 직접 열어서 쓰기 실패를 흉내 낼 수 없습니다. 그래서 파일 여는 함수를 바꿔 끼울 수 있게만 고친 사본(`seam.patch`, 동작은 그대로)에 장애 주입 테스트(`gateway/internal/queue/queue_fault_test.go`)를 돌렸습니다. 결과는 `before.txt`입니다.

| 테스트 | 원래 코드 |
|---|---|
| 쓰기가 중간에 실패한 뒤 받은 사건이 재시작 후 남는가 (실패 지점 9가지) | 8가지 실패. 0바이트만 쓰인 경우만 통과 |
| 확인(ACK) 기록이 실패한 뒤에도 파일이 온전한가 | 실패 |
| 무작위 장애 300단계 × 40회에서 받은 사건을 잃지 않는가 | 40회 중 31회 실패 |
| 그 밖의 테스트(형식, 복구, 압축, 동시 사용) | 통과 |

`seam.patch`에는 원래 코드가 몇 줄 들어 있습니다.
