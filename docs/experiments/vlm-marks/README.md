# 발과 구역 안쪽을 표시하면 같은 장면의 안·밖을 모두 맞힐까?

**네 조건 모두 0/23쌍이었다.** 청록색 점과 빨간 음영, 두 문장의 설명을 함께 추가하자 전체 화면과 잘린 화면 모두 개별 정답도 0/46으로 줄었다. ‘안’을 맞히는 사례가 늘지 않았고 보류와 형식 오류가 늘었다.

## 비교 조건

사건 15건과 카메라 2대에서 진입·머무름 장면 23개를 사용했다. 같은 장면에서 원래 구역과 옮긴 구역을 한 번씩 물었다. 원래 구역에서는 `clearly_inside`, 이동 구역에서는 `outside`를 답해야 그 장면의 **쌍 정답** 1개로 센다. 항상 ‘밖’을 답하면 개별 정답은 23/46이지만 쌍 정답은 0/23이다. `near_boundary`와 `unclear`는 보류로 계산한다.

네 조건 모두 한 이미지에 시각 토큰 64개를 썼다. `full`은 전체 화면이고 `crop`은 사람 상자와 가까운 구역 경계를 담은 화면이다. `+marked`에서는 자르기 전에 빨간 안쪽 면을 불투명도 60%로 덧칠하고, 상자 아래 중앙에 검은 테두리를 두른 청록색 점을 그렸다. 빨간색은 기존 질문의 구역 색과 일치시키고, 청록색은 빨간 바닥 위에서도 발 좌표를 찾을 수 있게 골랐다. 점의 색·크기는 정답과 무관하다. 눈으로 확인할 대상은 점의 중심이다.

추가한 질문 문장은 다음과 같다.

> The center of the cyan dot marks the person's feet. The red shaded area is the inside of the restricted zone.

이 점은 추적 상자에서 계산한 좌표다. 화면에 실제 발이 보이지 않는 사례에도 점이 생긴다. 따라서 이 실험이 평가하는 것은 표시한 좌표와 다각형의 관계를 모델이 읽을 수 있는지다.

표시 없는 두 조건은 지난 실험의 [문항별 응답](../vlm-crop/result.json)과 원문이 각각 46/46개 일치했다. 이번에 추가한 조건에서는 같은 토큰 예산으로 안·밖을 읽는 데 실패했다. 특히 `full+marked`에서 오답이 0건인 이유는 46개 응답 모두 보류하거나 파싱에 실패했기 때문이다.

`crop+marked`의 형식 오류는 기존 2건에서 20건으로 늘었다. 응답 원문에는 네 선택지를 세로줄로 이어 되풀이한 사례와 숫자 `0.0.`만 반환한 사례(6건)가 있었다. 숫자를 사후에 안·밖으로 해석하지 않았다. 설명 추가로 입력 토큰이 144개에서 168개로 늘었지만 그림도 동시에 바뀌었으므로 문장 길이가 원인인지 확인하려면 별도 비교가 필요하다. 지연은 후반 일부 요청에서 크게 늘었다(최대 142.53초). 표는 중앙값이며 한 번의 실행으로 속도 우위를 판단하기 어렵다.

점의 반지름과 테두리 2px를 포함한 범위를 좌표로 점검했다. 46문항 모두 점 중심은 화면 안에 있었다. 원 둘레가 일부 잘린 문항은 전체 화면에서 24개, crop에서 28개였다. crop에서만 추가로 잘린 4개는 두 장면의 원래·이동 구역 쌍이다. 따라서 잘린 점을 살펴볼 필요는 있지만, 잘림 하나로 정답 0건을 설명하기는 어렵다.

## 결론과 다음 비교

이 설정의 SmolVLM-500M은 사람이 구분할 수 있게 점과 면을 표시해도 같은 장면의 안·밖을 모두 구별하지 못했다. 표시와 설명을 제품 입력에 채택할 근거는 얻지 못했다. 자료는 카메라 2대, 사건 15건, 모델 1개이며 ‘밖’은 같은 화면에서 구역을 옮겨 만든 대조 조건이다.

다음 실험에서는 같은 표시 이미지로 기존 질문과 설명을 붙인 질문을 비교해 문장 추가 효과를 본다. 이어 기존 질문을 고정하고 표시 유무를 바꿔 그림 효과를 본다. 답 형식의 영향은 동일 이미지와 설명에서 선택지 나열을 없앤 질문으로 따로 측정한다. 같은 입력을 다른 모델에도 주어야 이번 실패가 특정 모델에서 반복되는지 판단할 수 있다. 이 비교들은 아직 실행하지 않았다.

## 재현

측정 도구와 테스트의 기준 커밋은 `ddbdfda477ae10121eda2117de0aa6afaee25d8b`이다. 표시 함수를 커밋한 뒤 같은 커밋 `4392019e89b108f89cb02d026e25595702828e50`에서 전체 실험을 실행했다. 모델은 `HuggingFaceTB/SmolVLM-500M-Instruct`, 가중치 리비전은 `753c1752602b5e739af7a7fa6947a635051897a3`이다. greedy decoding, 최대 출력 48토큰, CPU 2스레드를 사용했다. 지연은 모델이 한 질문을 처리한 시간으로, 이미지에 표시를 그리는 시간은 포함하지 않는다.

```bash
python -m pytest tests/test_vlm_marks.py tests/test_vlm_crop_experiment.py -q
python -m sceneproof.eval.vlm_crop --dry-run --strategies full,crop --markings product,marked --save-images /tmp/vlm-marks
python -m sceneproof.eval.vlm_crop --strategies full,crop --markings product,marked --threads 2 --out docs/experiments/vlm-marks/result.json --save-images docs/experiments/vlm-marks/images
```

표시 테스트 12개와 측정 도구 테스트 32개가 통과했다. 문항별 원문·응답 길이·좌표·실행 환경은 [측정 결과](result.json), 같은 장면의 네 조건 입력은 [이미지 폴더](images/)에 있다.
