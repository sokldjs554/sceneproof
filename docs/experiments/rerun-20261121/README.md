# 설정 실험 다시 돌리기 (2026-11-21)

두 설정 실험([들어감 확인 시간](../entry-confirm-20261113/README.md), [최소 사람 상자 높이](../min-box-height-20261113/README.md))은 처음 실행할 때 커밋되지 않은 변경이 있었습니다(기록된 커밋 `aad33d0`은 저장소에 없음). 그래서 확정된 코드에서 같은 설정 세 가지(기본, 들어감 확인 1.0초, 최소 상자 40px)를 다시 돌렸습니다. 두 곳에서 돌렸습니다.

| | 처음 기록 (11/13) | 이 세션 (Claude Code) | 저장소 주인의 Mac |
|---|---|---|---|
| 코드 | `aad33d0` (커밋되지 않은 변경 포함) | `1fc1910` | `88d47d5`* |
| Python · ONNX Runtime | 3.12.14 · 1.31.1 | 3.13.18 · 1.31.1 | 3.12.8 · 1.19.2 |
| OpenCV · NumPy | 5.0.0 · 2.3.5 | 5.0.0 · 2.5.4 | 기록 없음 |
| 결과 파일 | `../entry-confirm-20261113/*.json`, `../min-box-height-20261113/*.json` | `session_*.json` | `mac_*.json` |

\* 사건 묶음 개선을 넣은 커밋입니다. 바뀐 곳은 검토 서버와 화면뿐이라 영상 분석 결과에는 영향이 없습니다. `1fc1910`과 분석 코드가 같습니다.

## 결과 (찾음 / 놓침 / 잘못 울림 / 중복, 평가 영상 4편)

| 설정 | 처음 기록 | 이 세션 | Mac |
|---|---|---|---|
| 기본 (들어감 확인 0.3초, 상자 높이 제한 없음) | 12 / 0 / 0 / 6 | 12 / 0 / 0 / 6 | 12 / 0 / 1 / 6 |
| 들어감 확인 1.0초 | 9 / 3 / 0 / 2 | 10 / 2 / 0 / 2 | 10 / 2 / 0 / 2 |
| 최소 상자 높이 40px | 12 / 0 / 0 / 6 | 12 / 0 / 0 / 6 | 12 / 0 / 1 / 7 |
| 주차장 끝 시각 오차, 기본 → 40px | 1.69 → 1.33초 | 1.69 → 1.33초 | 1.69 → 1.97초 |

- **들어감 확인 시간**: 세 곳 모두 1.0초에서 중복이 6 → 2건으로 줄고 놓침이 0 → 2~3건으로 늘었습니다. 기본값 0.3초를 유지한 결론은 그대로입니다. 확정된 코드에서 다시 잰 놓침은 3건이 아니라 2건입니다.
- **최소 상자 높이 40px**: ONNX Runtime 1.31인 두 곳에서는 처음 기록과 같았지만(끝 시각 오차 1.69 → 1.33초), Mac에서는 오히려 1.97초로 늘고 중복이 1건 늘었습니다. 이 설정의 효과가 실행 환경에 따른 차이보다 작다는 뜻입니다. 기본값을 끔으로 둔 판단(설계 결정 D15)이 더 분명해졌습니다.
- **Mac 기본 설정의 잘못 울림 1건**: 주차장 28.8초에 길이 0인 사건 하나가 더 생겼습니다. 같은 모델·같은 설정이어도 환경에 따라 탐지 결과가 조금 달라집니다.

## 왜 환경마다 다른가

같은 숫자(12 / 0 / 0 / 6)가 나온 처음 기록과 이 세션도 사건 목록을 하나씩 보면 시작·끝 시각이 조금씩 다르고, 캠퍼스·매장 영상에서는 사건 수도 다릅니다. 집계가 같았던 것은 우연에 가깝습니다. 원인으로 확인한 것은 두 가지입니다.

1. **평가 영상이 컴퓨터마다 다르게 만들어집니다.** `scripts/fetch_data.sh`는 원본을 내려받은 뒤 그 컴퓨터의 ffmpeg로 다시 인코딩합니다. 이 세션의 `campus-walkway.mp4` SHA-256은 `68800e7f…`로, 처음 기록에 적힌 `fe5aeb64…`와 다릅니다(다른 세 영상도 다름). 디코딩된 화면이 조금씩 달라지고, 경계선 근처의 탐지와 추적이 갈립니다.
2. **ONNX Runtime 버전**: Mac은 1.19, 나머지는 1.31입니다. Mac의 영상 해시는 기록되지 않아 두 원인을 나눌 수 없습니다.

같은 환경 안에서는 결과가 매번 같습니다. 이 세션의 기본 설정 결과는 11월 16일 같은 환경 실행과 비교한 값 291개가 모두 같았습니다.

## 다시 확인한 원인 (2026-11-23)

평가 환경을 이미지로 고정하면서 원인을 하나씩 재 봤습니다. 위 두 가지 설명은 맞지 않거나 부족했습니다. 확인된 원인은 세 가지입니다.

| 원인 | 측정 | 결과에 미치는 영향 |
|---|---|---|
| **영상을 읽는 방식** | 분석기는 GStreamer가 있으면 그것으로, 없으면 OpenCV로 영상을 읽습니다(`pipeline.source_backend: auto`). 같은 입력 파일·같은 라이브러리 버전에서 OpenCV로 읽으면(`session_base_opencv.json`) 주차장에 잘못 울림 1건이 생기고 캠퍼스·매장의 중복 수가 바뀝니다. | 가장 큼. Mac에는 GStreamer가 없었습니다. 이 세션에서 OpenCV로 읽은 결과는 Mac 기록과 4편 모두 집계가 같고(12 / 0 / 1 / 6), 3편은 사건 시각까지 같습니다. |
| **ffmpeg 스레드 수** | 같은 컴퓨터에서 `-threads`만 1, 2, 6으로 바꿔도 다른 파일이 나옵니다. 지정하지 않으면 CPU 코어 수로 정해집니다. 6으로 고정하면 코어 1·2·4개에서 모두 같은 파일이 나옵니다. | 컴퓨터마다 입력 영상이 달라집니다. `scripts/fetch_data.sh`가 이제 6으로 고정합니다(`FFMPEG_THREADS`). |
| **인코더가 쓰는 CPU 명령어** | 스레드를 고정해도 x264는 CPU가 지원하는 명령어에 따라 계산 방식을 고릅니다. 명령어를 AVX2까지로 제한하면 매장 영상만 다른 파일이 되고 나머지 3편은 같습니다. 코드스페이스(다른 CPU)에서도 매장 영상만 달랐습니다. | 영상을 컴퓨터마다 다시 인코딩하는 방식으로는 모든 컴퓨터에서 같은 파일을 보장할 수 없습니다. |

모델 파일은 원인이 아니었습니다. 공식 YOLOX-tiny ONNX 파일로 돌려도 이 세션 결과와 값 291개가 모두 같습니다. ONNX Runtime 1.19(Mac)의 영향은 따로 재지 않았습니다.

**고친 방법**: 평가 환경을 이미지(`deploy/docker/Dockerfile.eval`)로 고정했습니다.
- 기반 이미지는 다이제스트로, Python 패키지는 전부 정확한 버전으로(`deploy/docker/eval.constraints.txt`), ffmpeg·GStreamer 버전도 고정합니다.
- 영상은 다시 인코딩하지 않고, 이 세션 결과를 만든 영상 4편을 그대로 릴리스 [`eval-videos-v1`](https://github.com/sokldjs554/sceneproof/releases/tag/eval-videos-v1)에서 받습니다. 받은 뒤 `docs/eval/inputs.lock.json`과 해시가 다르면 빌드가 멈춥니다.
- 영상은 GStreamer로 읽습니다.
- 평가 결과에 입력 파일의 해시, 도구 버전(ffmpeg·GStreamer 포함), 커밋 번호가 남습니다(`src/sceneproof/eval/provenance.py`).

**확인**: 이 이미지로 코드스페이스와 GitHub 자동 검사(서로 다른 컴퓨터)에서 돌린 결과가 모두 이 세션의 기본 설정 결과(`session_base.json`)와 값 291개가 같습니다. 코드스페이스 결과는 `docs/eval/raw/event_eval_image_codespaces.json`, 점검은 `scripts/check_eval_image.sh`입니다(CI `eval-image` 작업).

## 다시 돌리기

평가 이미지로(어느 컴퓨터에서나 같은 입력·같은 도구):

```bash
docker build --build-arg GIT_COMMIT=$(git rev-parse --short HEAD) -f deploy/docker/Dockerfile.eval -t sceneproof-eval .
mkdir -p /tmp/out && chmod 777 /tmp/out
docker run --rm -v /tmp/out:/out sceneproof-eval --out /out/ev_base.json
```

이미지 없이(결과가 컴퓨터에 따라 달라질 수 있음):

```bash
python -m sceneproof.eval.run_eval --out /tmp/ev_base.json
python -m sceneproof.eval.run_eval --config docs/experiments/entry-confirm-20261113/slow.yaml --out /tmp/ev_slow.json
python -m sceneproof.eval.run_eval --config docs/experiments/min-box-height-20261113/min40.yaml --out /tmp/ev_min40.json
```
