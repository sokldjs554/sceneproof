# 연구용 벤치마크: 사람이 표시한 정답으로 잰 구역 사건 성능과 추가 학습 효과

이 문서는 `scripts/bench_report.py`가 `docs/eval/bench/raw/*.json`에서 만듭니다. 손으로 적은 숫자는 없습니다.

## 1. 데이터와 정답

| 데이터 | 라이선스 | 정답을 만든 방법 | 출처 표기 |
|---|---|---|---|
| caviar | Creative Commons BY-SA (as stated on the CAVIAR data page) | per-frame person boxes found by hand-labelling the images (CVML XML); people who never move during a clip may be unboxed (INRIA set) | EC Funded CAVIAR project/IST 2001 37540, http://homepages.inf.ed.ac.uk/rbf/CAVIAR/ |
| mot16 | CC BY-NC-SA 3.0 (MOTChallenge) | per-frame boxes annotated by hand following the MOT16 protocol (all persons incl. occluded and static ones) | Milan, Leal-Taixe, Reid, Roth, Schindler: MOT16: A Benchmark for Multi-Object Tracking, arXiv:1603.00831 |
| mot20 | CC BY-NC-SA 3.0 (MOTChallenge) | per-frame boxes annotated by hand following the MOTChallenge protocol | Dendorfer et al.: MOT20: A benchmark for multi object tracking in crowded scenes, arXiv:2003.09003 |

원본 영상은 저장소에 올리지 않습니다. `python scripts/fetch_bench.py`가 원래 사이트에서 내려받아 다시 인코딩합니다(영상 프레임 번호 = 정답 프레임 번호가 되도록). 제외한 데이터와 이유는 `configs/bench/sources.yaml`의 `excluded`에 있습니다.

**사건 정답은 사람이 그린 상자에서 만듭니다.** 데이터셋 작성자들이 프레임마다 손으로 그린 사람 상자를, 제품과 똑같은 구역 판정 코드(발 위치가 구역 안에 0.3초 이상 → 들어감, 0.8초 이상 밖 → 나감, 5초 이상 → 체류)에 넣습니다. 그래서 정답과 프로그램의 차이는 "상자를 누가 그렸는가(사람 vs 탐지기+추적기)" 하나뿐입니다. 구역 선 근처를 스친 경우는 '경계 통과'로 따로 두어 맞음도 틀림도 아닌 것으로 셉니다.

**프로그램이 낸 사건이 정답과 같은 사건인지**는 시간(겹침 0.5초 이상 또는 시작 1초 이내)과 사람(같은 순간 발 위치 차이가 그 사람 키의 절반 이하)을 모두 봅니다. 사람이 많은 장면에서 시간만 보면 다른 사람의 사건으로 점수를 받는 일을 막기 위해서입니다.

## 8. 재현

```bash
python scripts/fetch_bench.py                      # 원 사이트에서 86편 다운로드·재인코딩 (재인코딩한 영상 약 0.8GB, 프레임 수 = 정답 프레임 수 검사)
python -m sceneproof.eval.bench.run --split dev --candidate tiny-coco:models/yolox_tiny.onnx \
    --candidate s-coco:models/yolox_s.onnx:yolox_s --out docs/eval/bench/raw/bench_dev_baseline.json
python -m sceneproof.train.finetune --variant yolox_tiny --epochs 10   # CPU 4코어 약 1.7시간, 조정 분할로 회차 선택
python scripts/export_onnx.py --variant yolox_tiny --weights models/finetune/yolox_tiny_bench/best.pth \
    --out models/finetune/yolox_tiny_bench/best.onnx
python -m sceneproof.eval.bench.run --split dev --candidate tiny-ft:models/finetune/yolox_tiny_bench/best.onnx:yolox_tiny \
    --out docs/eval/bench/raw/bench_dev_finetuned.json
python -m sceneproof.eval.bench.run --split test --final   # configs/bench/final.yaml의 후보 전부, 한 번만 (이미 잠겨 있음)
# 측정 뒤 보완 (6절)
python -m sceneproof.train.finetune --out models/finetune/yolox_tiny_bench_v2   # 학습 정답 상자 수정 뒤 다시 학습
python scripts/export_onnx.py --variant yolox_tiny --weights models/finetune/yolox_tiny_bench_v2/best.pth \
    --out models/finetune/yolox_tiny_bench_v2/best.onnx
python scripts/fetch_bench.py --ids mot20-03,mot20-05   # 두 번째 최종 분할 영상
python -m sceneproof.eval.bench.run --split test2 --final  # configs/bench/final2.yaml, 한 번만 (이미 잠겨 있음)
python -m sceneproof.eval.bench.replay cache --model models/finetune/yolox_tiny_bench_v2/best.onnx \
    --ids mot16-04,mot20-01,mot20-02,mot16-02,mot16-09,@dev
python -m sceneproof.eval.bench.replay sweep --model models/finetune/yolox_tiny_bench_v2/best.onnx \
    --variants configs/bench/tracker_variants.json --group crowd=mot16-04,mot20-01,mot20-02,mot16-02,mot16-09 \
    --group dev=@dev --out docs/eval/bench/raw/bench_tracker_sweep.json
python scripts/bench_report.py
```

추가 학습은 스레드 순서 때문에 비트 단위로 같지 않을 수 있습니다. 최종 측정에 쓴 가중치는 `configs/bench/final.yaml`에 ONNX 해시로 적어 두었습니다.
