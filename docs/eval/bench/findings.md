# 연구용 벤치마크 — 결과를 읽는 법과 소견

표와 측정 조건은 [`README.md`](README.md)(자동 생성)에 있습니다. 여기 적은 숫자는 모두 `raw/bench_test_final.json`(최종 분할), `raw/bench_dev_*.json`(조정 분할), `raw/finetune_log.json`(학습)에서 옮긴 것입니다. 용어를 먼저 정리합니다.

- **찾은 비율(재현율)**: 사람이 실제로 구역에 들어간 사건 중 프로그램이 알린 비율. 높을수록 놓치는 사건이 적습니다.
- **맞힌 비율(정밀도)**: 프로그램이 알린 사건 중 실제로 사람이 들어간 비율. 높을수록 헛알림이 적습니다.
- **시간당 잘못 울림**: 실제로는 아무도 안 들어갔는데 울린 횟수를 영상 시간으로 나눈 값.
- **중복**: 한 사람의 한 번 출입이 사건 2개 이상으로 쪼개진 것. 틀린 것은 아니지만 담당자가 같은 일을 여러 번 보게 됩니다.

## 1. 한 줄 요약

**제품과 같은 작은 모델을 현장 종류의 데이터로 추가 학습하자, 본 적 있는 종류의 카메라에서는 놓치는 사건이 22건에서 1건으로 줄었습니다. 처음 보는 장소에서도 더 많이 찾았지만, 사람을 놓쳤다 다시 잡는 일이 늘어 같은 출입이 여러 사건으로 쪼개지는 문제가 새로 생겼습니다.**

## 3. 소견

1. **위에서 내려다보는 카메라는 기본 모델이 사실상 못 씁니다.** 로비 영상에서 기본 모델은 26건 중 7건만 찾았고(사람 찾기 AP50 0.085), 3배 큰 모델도 15건이었습니다. 원인은 학습 데이터의 차이로 보입니다. 공개 학습 데이터(COCO)의 사람 사진은 대부분 옆에서 찍었고, 천장 광각 카메라에서는 사람이 납작한 모양으로 보입니다. 같은 종류의 화면 9분 분량(학습 분할)으로 추가 학습하자 26건 모두 찾았습니다.
2. **"큰 모델로 바꾸면 되지 않나"는 답이 아니었습니다.** 큰 모델은 놓침을 47건에서 30건으로 줄였지만, 매장 정면 화면에서 잘못 울림이 시간당 57에서 96으로 늘었고 처리 시간이 약 3배입니다(§2 추론 성능, `docs/eval/README.md`). 추가 학습한 작은 모델은 속도와 배포 경로를 그대로 둔 채 놓침을 9건으로 줄였습니다.
3. **처음 보는 장소에서는 반드시 다시 재야 합니다.** 추가 학습 모델은 처음 보는 장소에서도 놓침을 25건에서 8건으로 줄였지만, 중복이 9건에서 43건으로 늘고 잘못 울림 6건이 생겼습니다. 진단해 보니 기차역 영상에서 "사람을 놓쳐서 닫힌 사건"이 40건에서 68건으로 늘었고, 한 사람이 3조각 이상으로 나뉜 경우가 0명에서 5명이 되었습니다. 추가 학습으로 작은 사람을 더 많이 찾게 됐지만(키 50픽셀 미만 재현율 0.37 → 0.70), 학습에 없던 1080p 혼잡 장면에서는 점수가 문턱 근처를 오르내려 추적이 자주 끊긴 것으로 보입니다. 광장 영상의 사람 찾기 AP50은 오히려 0.47에서 0.39로 떨어졌습니다. 정리하면 **추가 학습의 효과는 학습한 종류의 화면에서만 믿을 수 있고**, 새 현장에는 그 현장 영상을 조금이라도 넣어 다시 학습하고 재야 합니다.
4. **시간당 잘못 울림은 아직 믿을 만한 숫자가 아닙니다.** 처음 보는 장소는 모두 합쳐 2.8분이라, 잘못 울림 1건이 시간당 21건으로 계산됩니다(광장은 0.3분이라 1건이 180). 본 적 있는 장소 24.7분도 1건이 시간당 2.4건입니다. 현장에서 쓸 숫자를 얻으려면 몇 시간짜리 영상이 필요하고, 그 방법은 §5에 있습니다.
5. **매장 정면 화면의 잘못 울림은 세 모델 모두에 있습니다(6–15건).** 구역(매장 안)이 유리창과 진열대 너머까지 이어져, 유리에 비친 사람이나 마네킹 근처에서 울린 경우가 섞여 있을 수 있습니다. 사건별로 사진을 보고 원인을 나누는 일은 아직 하지 않았습니다.

## 4. 이 결과를 믿을 수 있는 이유와 한계

- 분할은 구역을 그리거나 무엇을 재기 전에 고정해 커밋했고(`configs/bench/split.yaml`, 해시 검사), 추가 학습의 회차는 조정 분할로 골랐으며, 후보 세 개는 최종 분할을 건드리기 전에 `configs/bench/final.yaml`로 고정했습니다.
- 최종 분할은 두 번 시작되었습니다. 1회째는 사람 찾기 점수 계산 버그로 결과를 하나도 저장하지 못하고 중단되었고, 고친 뒤 이유를 남기고 2회째를 돌렸습니다(`test_lock.json`, 개발 일지 L18). 후보·구역·설정은 바꾸지 않았습니다.
- 사건 정답은 데이터셋 작성자가 손으로 그린 사람 상자에서 제품과 같은 규칙으로 만들었습니다. 그러나 이 규칙으로 만든 "사건"을 사람이 직접 영상을 보고 표시한 것과 비교하는 일(두 사람 일치도)은 아직 하지 않았습니다.
- 데이터는 쇼핑몰·로비·거리·기차역입니다. 공장, 안전모·조끼를 입은 작업자, 지게차가 있는 장면은 없습니다. 연구용으로 사람 정답이 있는 공장 영상을 찾지 못했기 때문입니다.
- 정답 사건 207건 중 113건이 처음 보는 장소 3곳(그중 83건이 기차역 한 곳)에서 나와, 전체 합계는 기차역의 영향을 크게 받습니다. 장소별 줄을 함께 보세요.

## 5. 다음 단계

1. **두 사람 일치도** (사용자 작업): `tools/event_labeler/index.html`로 최종 분할 영상 몇 편을 두 사람이 따로 표시 → `python -m sceneproof.eval.bench.agreement A.json B.json --with-gt`. 사람끼리 얼마나 같은지, 데이터 상자로 만든 정답과 얼마나 같은지가 나옵니다.
2. **몇 시간짜리 영상의 시간당 잘못 울림** (사용자 촬영): 아무도 구역에 들어가지 않는 장면을 한두 시간 찍어 `python -m sceneproof.eval.bench.idle_review run --video ... --zone ...` → 울린 사건만 사람이 확인 → `score`.
3. **쪼개진 사건 줄이기** (개발): 같은 구역에서 몇 초 안에 가까운 위치로 다시 나타난 사건을 하나로 잇는 후처리, 또는 추적기의 문턱·유지 시간을 혼잡한 장면의 조정 데이터로 다시 맞추기. 최종 분할은 이미 썼으므로, 이 개선은 새로 고정한 별도 평가 데이터로 재야 공정합니다.
4. **현장 영상으로 추가 학습**: 실제 설치 현장의 영상 몇 분에 사람 상자를 그려 학습 분할에 넣는 것이 가장 효과가 큰 다음 단계입니다(§3-3).
